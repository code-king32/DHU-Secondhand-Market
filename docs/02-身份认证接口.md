# 身份认证与账号接口

本文件记录当前已实现的身份认证与账号接口，供前后端联调使用。验证码参数及注销限制描述当前实现；尚待团队确认的规则不视为最终需求。

## 公共约定

- 有请求体时使用 `Content-Type: application/json`，不使用表单提交。
- 登录凭据为 `JSESSIONID` Session Cookie，空闲超时为30分钟，Cookie 设置 `HttpOnly`、`SameSite=Lax`。注册成功不会自动登录。
- Postman 需保留 Cookie。浏览器跨端口请求需携带凭据，例如 `fetch` 使用 `credentials: 'include'`；本地前后端统一使用 localhost 或统一使用 127.0.0.1，避免混用。
- 本地默认允许的前端来源为 `http://localhost:5173`、`http://127.0.0.1:5173`，可通过 `app.web.allowed-origins` 设置逗号分隔的来源。写请求检查 Origin，缺少 Origin 时检查 Referer；`Sec-Fetch-Site: cross-site` 或不受信任的来源、非 JSON 内容类型会被拒绝，返回403。无请求体的动作可不设置 Content-Type。
- 请求身份、角色从 Session 和数据库确定；注册只能创建 USER，不能通过请求字段指定管理员、用户编号、认证或账号状态。
- 错误响应使用 HTTP 状态码和 `{"message":"错误说明"}`。下文列出业务状态；来源检查可能在业务处理之前返回403。

| 方法与路径 | 用途 | 成功状态 |
|---|---|---|
| POST /api/auth/registration-codes | 向未注册校园邮箱发送验证码 | 200 已投递 / 202 待重试 |
| GET /api/auth/registration-codes/{deliveryId} | 查询该次邮件发送状态 | 200 |
| POST /api/auth/register | 使用验证码注册 | 201 |
| POST /api/auth/login | 邮箱密码登录并创建 Session | 200 |
| POST /api/auth/logout | 退出当前 Session | 204 |
| GET /api/auth/me | 当前登录用户信息 | 200 |
| PATCH /api/account/me | 修改当前用户昵称 | 200 |
| DELETE /api/account/me | 密码确认注销账号 | 204 |
| GET /api/users/{id} | 公开用户资料 | 200 |

## 用户信息响应

注册、登录、本人信息和修改昵称返回相同结构，例如：

```json
{
  "id": 1,
  "email": "student@mail.dhu.edu.cn",
  "nickname": "校园同学",
  "emailVerified": true,
  "status": 0,
  "role": "USER",
  "createdAt": "2026-10-21T10:00:00"
}
```

`status` 为0正常、1禁用、2注销，`role` 为 USER 或 ADMIN。此结构用于注册结果及本人操作，邮箱不出现在下文的公开资料接口中。接口不返回密码、密码哈希、验证码或验证码哈希。时间以实际响应为准，示例值不代表固定数据。

## 发送注册验证码

`POST /api/auth/registration-codes`

请求头：`Content-Type: application/json`。

请求体中的 `email` 填写用户自己的校园邮箱：

```json
{
  "email": "你的校园邮箱地址"
}
```

允许的邮箱域名为 `mail.dhu.edu.cn` 和 `dhu.edu.cn`，按完整域名匹配。邮箱统一转为小写保存；该接口用于尚未注册的邮箱。

成功响应为 HTTP 200：

```json
{
  "message": "验证码已发送",
  "expiresInSeconds": 300,
  "resendAfterSeconds": 60,
  "deliveryId": "00000000000000000000000000000000",
  "status": "SENT"
}
```

服务端生成六位数字验证码，验证表保存 BCrypt 哈希。验证码和投递任务先在短事务中同时提交，再调用 SMTP；验证码有效期为五分钟，同一邮箱两次发送请求至少间隔六十秒。重新获取会替换旧码、清零错误次数、清除消费时间并取消旧待发任务。邮件投递结果不确定时仍保留已提交的验证码，避免已收到的邮件因发送异常被回滚作废。

待重试任务中的验证码使用 AES-GCM 加密，成功、取消、到期或重试耗尽后清除密文。默认密钥文件 `uploads/mail-code.key` 自动生成并被 Git 忽略，重启及迁移时需保留该文件。任务状态为 PENDING、SENDING、SENT、FAILED、EXPIRED、CANCELLED；通过随机 `deliveryId` 查询，响应不包含邮箱、验证码或密文。SENT 代表 SMTP 接受邮件，仍需确认实际收件。

| HTTP 状态 | 含义 |
|---|---|
| 400 | 请求体、邮箱格式或校园邮箱域名不符合要求 |
| 409 | 邮箱已经注册 |
| 429 | 重发过快或超过邮箱、IP、全局发送限额，Retry-After 给出等待秒数 |
| 502 | 不可重试的发信失败或重试耗尽；验证码保留，先检查邮箱 |

错误响应的结构为：

```json
{
  "message": "发送过于频繁，请稍后重试"
}
```

首次发送仍同步等待 SMTP，但不占用业务数据库事务。临时失败返回202，由后台任务默认每5秒检查到期任务，最多尝试3次，失败后分别等待15秒、30秒；认证失败直接结束。重试沿用同一码，过期、已消费或被新码替代的任务不会继续发送。任务用120秒租约处理进程中断；SMTP 与数据库无法实现一次原子提交，因此极端情况下可能收到重复的同码邮件，不保证仅投递一次。

### 登录与发信限流

默认登录同IP每10分钟最多30次，同账号连续尝试最多5次；登录成功清除账号计数，但不清除IP计数。邮件同IP每小时20次、24小时100次，同邮箱24小时10次，全局24小时1000次；原有同邮箱60秒间隔仍生效。窗口从首次计数开始，不按自然日零点重置。限制返回429和 `Retry-After`。

参数见 `application.properties` 中的 `app.abuse.*`。限流状态为有容量上限的进程内计数，重启会清空，适用于当前单实例部署；多实例部署需共享计数。默认取连接对端IP，不信任客户端自报的 `X-Forwarded-For`；使用反向代理时需单独配置受信任代理。校园共享出口下可按实际人数调整IP限额。

## 注册

`POST /api/auth/register`

```json
{
  "email": "student@mail.dhu.edu.cn",
  "code": "123456",
  "password": "ExamplePass123!",
  "nickname": "校园同学"
}
```

示例验证码仅展示格式，实际应填写邮件中的六位数字。邮箱格式合法、最长254字符，域名与发送接口一致；校验后规范化为小写。密码至少8个字符，UTF-8 编码不超过72字节，不能仅按字符数判断多字节密码。昵称必填，请求字段最长50字符，保存前去除前后空白并拒绝空白昵称。

成功返回201及用户信息，`emailVerified=true`、`status=0`、`role=USER`。创建用户和消费验证码在同一事务中完成；同一码不能重复注册，并发注册最多成功创建一个账号。成功后需调用登录接口。

| HTTP 状态 | 含义 |
|---|---|
| 400 | 请求参数非法，验证码不存在、已过期、已消费或未达锁定阈值的验证码错误 |
| 409 | 创建账号时邮箱唯一性冲突 |
| 429 | 第五次验证码匹配错误，或该码已累计五次错误 |

匹配错误会持久化累计次数，达到五次后正确验证码也不能注册，需要重新获取。重发成功清零错误次数，仍受六十秒发送间隔约束。注册返回429不附带发送接口的 Retry-After。已注册账号再次提交旧的已消费验证码可能先返回400，不能一律按409处理。

## 登录

`POST /api/auth/login`

```json
{
  "email": "student@mail.dhu.edu.cn",
  "password": "ExamplePass123!"
}
```

成功返回200及用户信息，创建新的 Session；当前请求已有的 Session 会失效。保存服务端返回的 Cookie，用于后续本人操作。登录请求邮箱必填、合法、最长254字符；密码必填、最长72字符，UTF-8 超过72字节会被当作不匹配处理。

| HTTP 状态 | 含义 |
|---|---|
| 400 | 请求字段、邮箱格式或校园域名不符合要求 |
| 401 | 账号不存在或密码不匹配，统一提示邮箱或密码错误 |
| 403 | 密码匹配但账号不可用，例如被禁用、已注销或未认证 |

注销会清空密码哈希，因此注销后的登录通常先因密码不匹配返回401；客户端不应仅按一个固定状态码识别所有不可用账号。

## 退出与本人信息

`POST /api/auth/logout` 无需请求体，成功返回204、无响应体。没有 Session 时重复调用仍返回204；仅退出当前 Session。

`GET /api/auth/me` 返回当前用户信息。受保护接口无登录凭据、Session 超时或版本失效时返回401；账号禁用、注销或未认证时可能先返回403并使当前 Session 失效。禁用及恢复会递增会话版本，恢复后旧会话仍不能使用，需要重新登录。

## 修改昵称

`PATCH /api/account/me`，要求有效登录及正常、已认证账号：

```json
{
  "nickname": "新昵称"
}
```

请求字段必填、最长50字符，保存前去除前后空白，空白昵称返回400。成功返回200及更新后的用户信息。当前仅支持昵称，不提供邮箱、密码或角色修改；更新时账号状态变化导致未成功写入返回409。

## 注销账号

`DELETE /api/account/me`，要求有效登录，JSON 请求体确认当前密码：

```json
{
  "password": "ExamplePass123!"
}
```

成功返回204、无响应体。当前 Session 失效，其他 Session 后续请求也不能继续使用。账号状态设为注销，清空密码哈希，昵称改为“已注销用户”；保留账号记录和历史交易关联，邮箱唯一性仍保留，不能用相同邮箱重新注册。

- 密码错误返回400，响应包含 `code: "PASSWORD_MISMATCH"` 和 `message`，当前 Session 保持有效；必填校验不通过返回400。未登录仍返回401（`AUTH_REQUIRED`），旧会话失效返回401（`SESSION_EXPIRED`），客户端不能将密码确认失败视为会话失效。
- 管理员账号不能自行注销，返回409。
- 参与 ACCEPTED 交易时不能注销，返回409；先完成或取消该交易。
- 允许注销时，本人待售商品下架，本人参与的 PENDING 交易申请取消；处理与账号注销在同一事务中完成。
- 注销事务锁住账号后会再次校验账号状态、邮箱认证和会话版本；等待期间账号被禁用、注销或旧会话被撤销时，拒绝继续注销，不更改商品或交易。注销提交后，即使并发退出使 Session 消失或已失效，也保持204成功响应。

## 公开资料

`GET /api/users/{id}` 无需登录，返回200，例如：

```json
{
  "id": 1,
  "nickname": "校园同学",
  "emailVerified": true,
  "createdAt": "2026-10-21T10:00:00"
}
```

不存在、禁用或已注销账号返回404。公开响应不包含邮箱、角色或密码相关字段。信誉摘要见[信誉治理及扩展接口](05-信誉治理及扩展接口.md)。

## 数据库与测试

启动前完成 README 中的建库迁移，账号除基础字段外还需要 `role`、`session_version`。相关脚本为 `sql/01_user.sql`、`sql/02_registration_email_code.sql`、`sql/03_user_role.sql`、`sql/07_session_version.sql`；完整注销联动还依赖商品交易表，应按 README 执行全部脚本。

在 backend 目录运行：

```powershell
mvn "-Dtest=RegistrationCodeTests,AcceptanceFlowTests,RuntimeHttpTests" test
```

测试使用独立 H2 和邮件替身，覆盖发送限流、短事务提交、任务恢复、同码重试、到期与取消、验证码消费和锁定、并发注册、角色字段注入、密码字节边界、会话轮换和退出、公开字段、注销联动、账号禁用恢复及请求来源保护。RuntimeHttpTests 启动真实 HTTP 端口，数据库仍为 H2。普通业务测试关闭后台任务和限流以隔离用例，专门的限流测试单独启用并检查429与Retry-After。

显式运行真实 MySQL 认证存储测试：

```powershell
mvn "-Dtest=ManualDatabaseConnectionTests" "-Ddb.test.enabled=true" test
```

该测试替换邮件发送器，测试写入回滚。`ManualAcceptanceFlowTests` 还启动真实 HTTP 端口，使用独立用户 Cookie 和真实 MySQL 串起注册登录、交易、评价、治理及注销，核对跨请求提交结果，结束时精确清理随机测试数据；邮件仍使用替身。当前验收证据、手工步骤及待确认规则见[联调验收清单](06-联调验收清单.md)。
