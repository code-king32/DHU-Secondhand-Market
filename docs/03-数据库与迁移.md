# 数据库与迁移

本文件统一说明 MySQL 结构来源、初始化顺序和升级边界。当前使用 MySQL 8.0，开发库为 `dhu_secondhand`，独立验收库为 `dhu_secondhand_acceptance`。测试目录中的 H2 SQL 仅供自动化测试，不用于初始化 MySQL。

## 1. 结构来源

PowerShell 初始化脚本共用 [schema-manifest.json](../sql/schema-manifest.json)：先执行7份业务建表/迁移，再执行运行时辅助表脚本。

| 顺序 | 文件 | 作用及重复执行边界 |
|---|---|---|
| 01 | [01_user.sql](../sql/01_user.sql) | 用户基础表；不可在已有同名表上重跑 |
| 02 | [02_registration_email_code.sql](../sql/02_registration_email_code.sql) | 注册验证码表；不可在已有同名表上重跑 |
| 03 | [03_user_role.sql](../sql/03_user_role.sql) | 添加角色字段；字段存在时不可重跑 |
| 04 | [04_marketplace.sql](../sql/04_marketplace.sql) | 商品、交易表；仅幂等建表，不升级旧字段 |
| 05 | [05_community.sql](../sql/05_community.sql) | 评价、治理、收藏、求购等7张表；仅幂等建表 |
| 06 | [06_marketplace_visibility.sql](../sql/06_marketplace_visibility.sql) | 刷新商品状态约束，支持 `HIDDEN`；依赖原约束名 |
| 07 | [07_session_version.sql](../sql/07_session_version.sql) | 添加会话版本；字段存在时不可重跑 |
| 最后 | [runtime-schema.sql](../backend/src/main/resources/sql/runtime-schema.sql) | 邮件投递、图片归属及引用3张表，`CREATE TABLE IF NOT EXISTS` |

`04` 对新表已包含 `HIDDEN`，`06` 保留用于兼容历史表；初始化仍按上述顺序执行。辅助表 SQL 保留在后端资源目录，脚本和应用共用该文件，不另外复制一份。

## 2. 应用表清单

| 表 | 职责与关键关联 |
|---|---|
| `app_user` | 邮箱唯一、密码哈希、昵称、认证状态、账号状态、角色、会话版本 |
| `registration_email_code` | 每邮箱一条当前验证码哈希、过期/发送/消费时间、失败次数 |
| `market_goods` | 关联卖家，保存价格、分类、JSON图片地址列表和商品状态 |
| `market_trade` | 关联商品及买卖双方，保存申请价格快照、状态及双方确认位 |
| `community_review` | 关联完成交易和评价双方，交易与评价人组合唯一 |
| `community_report` | 举报人、目标类型/编号、理由、处理状态及结果 |
| `community_appeal` | 关联举报，每个举报最多一条申诉 |
| `community_audit` | 举报创建、处理、申诉及商品恢复的审计记录 |
| `community_user_audit` | 管理员禁用/恢复账号的审计记录 |
| `community_favorite` | 用户和商品组合唯一 |
| `community_wanted` | 求购发布者、预算、分类、开放/关闭状态 |
| `app_mail_delivery` | 邮件投递任务、加密载荷、重试次数、租约及到期时间 |
| `app_uploaded_image` | 图片文件名、所有者、大小、闲置时间及清理状态 |
| `app_goods_image` | 商品与本地图片的引用关系，组合主键 |

共14张应用表，其中11张业务表、3张运行时表。独立验收库额外包含工具标记表 `_acceptance_meta`，不属于业务结构。举报目标是多类型关联，部分辅助关系由应用维护，不能假定所有字段都有数据库外键。

分类为固定枚举 `TEXTBOOK`、`ELECTRONICS`、`DAILY`、`CLOTHING`、`OTHER`，没有独立分类表。交易是线下申请与双方确认，不包含付款、发货、收货等订单字段。

## 3. 新环境初始化

从仓库根目录使用 PowerShell 7：

```powershell
# 只查看计划，不连接数据库
./tools/Initialize-Database.ps1 -Preview

# 实际创建开发库，mysql 交互读取密码
./tools/Initialize-Database.ps1 -DatabaseUser root
```

可指定 `-DatabaseHost`、`-DatabasePort`，以及 `-MySql 'C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe'`。脚本固定目标库名、不接收密码参数；使用批处理遇错停止，已有同名库时拒绝初始化。MySQL DDL 不会整体回滚，若中途失败，应检查已执行到哪一步后处理，不能假定数据库仍为空。

不使用 PowerShell 时，可在仓库根目录启动 `mysql -u root -p`，手动执行：

```sql
CREATE DATABASE dhu_secondhand CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
SOURCE sql/01_user.sql;
SOURCE sql/02_registration_email_code.sql;
SOURCE sql/03_user_role.sql;
SOURCE sql/04_marketplace.sql;
SOURCE sql/05_community.sql;
SOURCE sql/06_marketplace_visibility.sql;
SOURCE sql/07_session_version.sql;
SOURCE backend/src/main/resources/sql/runtime-schema.sql;
```

手动执行时每一步确认成功后再继续，`SOURCE` 路径相对于 MySQL 客户端启动目录。验收库使用[验收包](../tools/acceptance/README.md)初始化，禁止把固定演示账号写入开发或正式数据库。

## 4. 已有数据库升级

先备份，并核对 `information_schema.columns` 和 `SHOW CREATE TABLE`，仅执行缺失的字段或约束迁移。不要对已有库运行整套初始化脚本，也不要使用 H2 的 `DROP ALL OBJECTS` 测试脚本。

应用默认 `spring.sql.init.mode=always` 只幂等创建3张辅助表，不会自动补齐用户角色、会话版本或修改历史业务表。生产环境由维护人员预建全部结构，再使用 `spring.sql.init.mode=never`；此时运行账号可以不授予建表权限。

现有 `ManualSchemaMigrationTests` 可补齐部分业务结构，但会直接修改开发库，只有显式选择 `./tools/Test-Backend.ps1 -Suite Schema` 才运行；它不是通用迁移框架，也不代替备份和结构核对。运行时辅助表须按本文件单独核对。

## 5. 数据维护与恢复

账号采用状态注销，保留历史关联；不通过直接删除用户解决禁用或注销问题。图片、交易、举报状态由业务接口维护，直接改库会绕开锁、引用与审计处理。

备份范围为数据库、图片目录及邮件任务密钥。已有完整站内图片 URL 的商品，在编辑保存时转换为规范地址并补登记引用；本次文件整理不扫描或修改已有商品数据。恢复环境时按[运行与部署](07-运行与部署.md)保持文件、密钥和数据库对应。
