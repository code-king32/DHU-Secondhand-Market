| 角色 | 当前职责 | 交接内容与状态 |
|---|---|---|
| A（组长） | 项目统筹、质量保障、独立测试与建议、系统集成及部署，参与独立功能开发 | 接口验收材料已准备，独立执行结果待登记 |
| B | Vue前端工程、页面组件、交互、API对接及前端测试 | 维护前端工程、接口对接与联调进度；本仓库尚未纳入前端工程 |
| C（后端） | MySQL模型、Spring Boot后端、业务接口、权限、事务和接口测试 | 提供代码、SQL、接口文档、测试证据和验收包，配合问题修复与联调 |

接口测试包括C的开发回归和A的独立验收。A检查正常、异常、权限与状态变化，补充用例、提出可复现问题和改进建议，组织修复复测。

## 2. 项目目标与范围

面向校园用户提供二手商品信息发布、检索与线下交易协作，交付可运行、可演示的Web系统。

- 核心：校园认证、账号注册与注销、商品发布与检索、线下交易、信誉评价、举报申诉。
- 扩展：收藏、求购、教材分类筛选。
- 图片当前保存HTTP/HTTPS地址，未提供二进制文件上传。
- 当前范围不包含在线支付、物流、实时聊天。邮箱变更、交易超时等尚无已确认方案。

## 3. 技术架构与当前实现

| 层 | 当前设计或实现 |
|---|---|
| 前端 | 任务书采用Vue 3、TypeScript、Vite；工程尚未纳入本仓库 |
| 后端 | Java 17、Spring Boot 3.5.16、Spring MVC，模块化单体REST API |
| 数据访问 | MyBatis-Plus 3.5.17与JdbcTemplate |
| 数据库 | MySQL 8.0，结构及迁移脚本位于sql目录 |
| 认证 | 校园邮箱验证码、BCrypt、Session Cookie |
| 邮件 | Spring Boot Mail、SMTP；自动化回归使用邮件替身 |
| 测试 | JUnit 5、MockMvc、H2、可显式开启的真实MySQL与HTTP测试、Postman验收集合 |
| 构建 | Maven |

请求经过Controller参数校验和会话/角色检查，由Service处理业务与事务，再通过Mapper或JdbcTemplate访问MySQL。前端独立调用JSON接口，当前不使用服务端页面模板，也没有引入Redis或消息队列。

代码位于 `com.dhu.secondhand`，按 `identity`、`account`、`marketplace`、`community`、`common` 组织。治理和信誉逻辑位于community包中，业务概念不等于必须拆成独立应用。

## 4. 数据模型与接口契约

数据库结构以仓库sql目录的01至07脚本为准：

| 表 | 用途 |
|---|---|
| app_user | 校园账号、密码哈希、昵称、角色、账号状态、会话版本 |
| registration_email_code | 邮箱验证码哈希、期限、发送间隔、失败计数及消费状态 |
| market_goods | 商品、卖家、分类、图片地址及在售/交易中/售出/下架/隐藏状态 |
| market_trade | 申请双方、成交价格快照、交易状态及双方确认标记 |
| community_review | 完成交易后的双方评价 |
| community_report、community_appeal | 举报、处理结果和申诉 |
| community_audit、community_user_audit | 举报申诉处理及账号状态变更审计 |
| community_favorite、community_wanted | 收藏与求购 |

初始化和迁移顺序见[README](../README.md)。已有库只执行缺失迁移，不重复建表。独立验收库的标记表属于测试工具，不是正常业务表。

所有业务接口以 `/api` 开头。成功响应直接返回对象或分页结构，部分操作返回204；异常使用对应HTTP状态码及带 `message` 的JSON对象，不使用早期设计的统一 `code/msg/data` 包装。

- [身份与账号接口](02-身份认证接口.md)：邮箱验证码、注册登录、会话、个人资料及注销。
- [商品与交易接口](04-商品交易接口.md)：发布、检索、上下架、申请、接受、确认及取消。
- [信誉治理及扩展接口](05-信誉治理及扩展接口.md)：评价、举报申诉、管理员处理、收藏与求购。

前端和测试调用者需保持JSESSIONID Cookie；跨源前端按接口文档携带凭据，后端核对允许来源。图片使用地址数组，不能按文件上传接口对接。

## 5. 当前交易流程与规则边界

买家申请后生成PENDING交易；卖家接受后为ACCEPTED，商品进入TRADING。双方分别确认后交易COMPLETED、商品SOLD；未完成交易可以取消。当前没有付款、发货或收货状态。

同一在售商品允许不同买家申请。当前实现接受一笔后阻止新申请，取消已接受交易后恢复在售，完成后取消其余待处理申请。这些细节以及验证码参数、评价、申诉和注销约束的最终确认状态，统一记录在[验收清单](06-联调验收清单.md)，不因代码或测试已存在就记为团队最终接受。

## 7. 协作和交接约定

1. C提供接口文档、SQL、启动说明、测试证据及[独立验收包](../tools/acceptance/README.md)，接口变更同步告知调用方并更新文档。
2. A独立运行带断言的接口测试，补充边界场景、登记缺陷和建议；B对接页面、检查Cookie、来源配置和错误展示。
3. 问题记录包含版本、环境、身份、前置数据、请求、预期与实际结果；C复现修复后由提出者复测。产品建议与缺陷分别说明，规则变更经团队确认。
4. 使用个人功能分支，经Pull Request审核后合并；推送、PR和合并是不同状态。当前后端分支为backend-bootstrap，实际状态以Git记录为准。
5. 本地配置和私人凭据不提交；演示账号只用于固定独立验收库，初始化、重置和清理遵守验收说明。
6. 课程材料和代码仓库分别提交；公共材料由组长统筹，个人材料由各成员负责，具体格式和期限以课程通知为准。
