# 项目设计文档

本文描述当前仓库实现。需求与成员职责以[课程任务书](软件项目管理课程任务书.docx)及[项目 README](../README.md)为依据；尚待确认的业务规则统一列在[验收清单](06-联调验收清单.md)。旧版中的 Thymeleaf 页面、支付物流订单、Redis 缓存和延迟队列均不属于当前实现。

## 1. 项目范围

平台面向东华大学师生，支持校园邮箱注册、商品发布与检索、线下交易申请和双方确认、评价、举报申诉、管理员治理、收藏和求购。普通用户可同时充当买家与卖家；管理员由维护人员设置角色，不能通过注册取得该权限。

当前不提供在线支付、物流、即时通信、修改或找回密码、邮箱变更、自动交易超时，以及被处罚者申辩流程。相关能力不能从页面、文档示例或预留字段推断为已经完成。

## 3. 请求和模块组织

```text
浏览器 / Postman
      │ HTTP、JSON、Session Cookie
      ▼
Controller：接收请求及 Bean Validation
      │ 身份与权限检查
      ▼
业务处理：状态机、归属关系、事务和行锁
      │
      ├── MyBatis-Plus UserMapper / 注册验证码 Mapper
      ├── JdbcTemplate：商品、交易、治理和辅助表
      └── 本地文件、SMTP（不在发信期间持有业务事务）
```

根包为 `com.dhu.secondhand`，按业务组织，实际位置如下：

| 包 | 职责 |
|---|---|
| `identity` | 验证码、邮件投递、注册登录、密码验证 |
| `account` | 用户实体与 Mapper、公开资料、昵称、账号注销扩展点 |
| `marketplace` | 商品、图片、交易状态及注销时商品交易处理 |
| `community` | 评价、信誉、举报、申诉、审计、收藏、求购 |
| `common` | Session 校验、来源检查、错误响应、限流、可信代理、后台任务 |

当前部分账号操作直接在 Controller 中使用 JdbcTemplate 和 TransactionTemplate，商品与社区 DTO 包括 record 类型；本次文件统一整理不改动这些实现，也不要求不存在的 `ServiceImpl`、统一实体类或通用响应包装。

## 4. 接口公共约定

- 业务接口统一位于 `/api`，HTTP 方法与状态码表达操作结果；具体路径见各模块接口文档。
- 成功直接返回业务 JSON，创建通常为201，删除和退出通常为204且无响应体。没有额外的 `Result{code,msg,data}` 包装。
- 错误以 HTTP 状态码和 `message` 为基本契约，部分业务错误附带可选字符串 `code`，例如 `PASSWORD_MISMATCH`、`AUTH_REQUIRED`、`SESSION_EXPIRED`。不是所有错误都有 `code`。
- 常见错误为400参数或业务输入错误、401未登录或凭据错误、403权限或来源拒绝、404不存在、409状态冲突、413文件超限、429限流；验证码发信不可重试失败可返回502。
- 分页字段为 `items`、`total`、`page`、`size`，JSON 字段顺序不作为契约。商品交易每页最多100条，社区接口最多50条，均限制最大页码。
- 有请求体的业务请求使用 JSON；图片上传是 multipart 例外。来源、Cookie 和代理约定见[身份接口](02-身份认证接口.md)及[运行与部署](07-运行与部署.md)。

## 5. 主要业务状态

| 对象 | 状态及规则 |
|---|---|
| 用户 | `0`正常、`1`禁用、`2`注销；角色 `USER` / `ADMIN` |
| 商品 | `ON_SALE`在售、`OFF_SHELF`下架、`TRADING`交易中、`SOLD`已售、`HIDDEN`管理员隐藏 |
| 交易 | `PENDING`申请 → `ACCEPTED`接受 → 双方确认后 `COMPLETED`；未完成可 `CANCELLED` |
| 举报 | `OPEN`待处理 → `RESOLVED`成立或 `REJECTED`驳回 |
| 申诉 | `OPEN` → `UPHELD`或 `REJECTED`；成立后重开原举报，处置不自动撤销 |
| 求购 | `OPEN` / `CLOSED` |

多个买家可对在售商品申请。接受一笔后锁定商品，其他待处理申请保留；完成后取消其余待处理申请。取消已接受交易后恢复在售。评价要求完成交易，双方各一次，评分1至5分。

隐藏商品只能由管理员解除隐藏并记录原因；未售商品先恢复下架，有成交记录的保持已售。账号注销前须结束已接受交易，事务内复核身份和状态；注销时下架待售商品、取消待处理申请并撤销会话。

## 6. 数据与可靠性

11张业务表和3张运行时辅助表的职责、约束及初始化入口见[数据库与迁移](03-数据库与迁移.md)。交易关键操作采用数据库事务和账号、商品、交易行锁；图片引用随商品事务提交，后台只清理超过保留期的未引用文件。

验证码验证保存 BCrypt 哈希；待投递任务使用 AES-GCM 保存可恢复验证码，密钥保存在本地文件。SMTP 发送位于业务事务之外，任务有限重试并以租约恢复中断；不保证邮件仅发送一次或一定进入收件箱。

默认 Session 和限流计数均为单实例内存状态；多实例共享会话、共享限流和文件存储不在当前部署方案内。真实 MySQL、SMTP、代理及浏览器行为仍须单独验收。

## 7. 文件维护规则

- 公共默认参数集中在 `backend/src/main/resources/application.properties`；环境连接及凭据使用 `backend/config/` 示例生成的本地文件或环境变量。
- 初始化顺序以 `sql/schema-manifest.json` 为脚本入口清单。历史 SQL 不重命名，测试专用 H2 SQL 不用于生产。
- 接口细节只在对应接口文档维护；测试结果只在验收清单维护；运行命令、代理和备份说明在运行与部署文档维护。
- 测试通过、提交 Git、合并 PR 和正式部署是不同状态，分别记录。涉及业务规则的调整须同步实现和测试，本次文档、配置、脚本整理不改变接口或业务规则。
