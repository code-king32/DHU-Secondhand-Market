- [ ] 管理员角色由维护人员设置，注册接口不能指定 ADMIN；使用独立测试账号和商品记录，避免操作正常业务数据。

## 核心手工流程

操作路径和请求字段分别见[身份与账号](02-身份认证接口.md)、[商品交易](04-商品交易接口.md)、[信誉治理及扩展](05-信誉治理及扩展接口.md)。以下勾选仅用于后续实际验收，目前均未勾选。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | POST /api/auth/registration-codes，填写自己的校园邮箱 | 200，收到六位随机验证码；响应不包含验证码 |
| 2 | 六十秒内向同邮箱重发 | 429，并有 Retry-After |
| 3 | POST /api/auth/register，使用实际邮件验证码 | 201，普通用户且已认证；尚未登录 |
| 4 | POST /api/auth/login，再 GET /api/auth/me | 200，Cookie 生效，可读取本人信息 |
| 5 | 卖家 POST /api/goods | 201，记录 goodsId，搜索和分类能检索到在售商品 |
| 6 | 买家 POST /api/trades，提交 goodsId | 201，记录 tradeId，交易为 PENDING |
| 7 | 卖家 POST /api/trades/{id}/accept | 200，交易 ACCEPTED，商品 TRADING |
| 8 | 买家 POST /api/trades/{id}/confirm | 200，仅买家确认，交易仍 ACCEPTED |
| 9 | 卖家调用同一 confirm 接口 | 200，交易 COMPLETED，商品 SOLD，退出在售列表 |
| 10 | 双方分别 POST /api/reviews | 各201；重复评价409；信誉数量和均分更新 |
| 11 | POST /api/auth/logout，再请求本人信息 | 204 后本人信息401 |

- [ ] 卖家、买家注册登录完成，身份会话隔离正确。
- [ ] 发布、检索、申请、接受、双方确认、评价闭环完成。
- [ ] 默认以数据库实际结果核对状态，不只根据页面提示判断。

## 异常与扩展验收

使用不同测试记录验证，避免在已完成交易上继续测试取消等不相容分支。

- [ ] 验证码错误、过期和已消费均不能注册；第五次匹配错误返回429，重新获取受发送间隔约束。
- [ ] 未登录不能发布；买家不能编辑卖家商品，不能接受他人的交易申请；非参与者不能读取交易详情。
- [ ] 同一买家重复申请被拒绝；不同买家可分别申请在售商品；接受一笔后不能再接受其他申请。
- [ ] 取消 ACCEPTED 交易后商品恢复在售；完成交易后其余 PENDING 自动取消，已完成交易不能取消。
- [ ] 有 ACCEPTED 交易时注销409；处理完该交易后注销成功，待售商品下架、PENDING 取消、其他旧会话失效。
- [ ] 收藏重复添加保持一条，取消幂等；求购可搜索和关闭，其他人不能关闭。
- [ ] 完成举报、管理员处理、举报人申诉、管理员处理申诉，检查权限、状态及审计记录。
- [ ] 管理员隐藏商品后卖家不能重新上架；禁用再恢复用户后，旧 Session 仍不可用，重新登录才可继续。
- [ ] 前端使用正确的 Cookie、JSON 和来源配置；切换身份、未登录、空列表及错误响应能正确展示。
