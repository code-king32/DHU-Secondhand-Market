## 2. 统一测试入口

从仓库根目录使用 PowerShell 7 执行：

```powershell
./tools/Test-Backend.ps1
```

默认显式关闭全部手动开关，不连接真实MySQL或发送邮件。`-Offline` 使用本机Maven缓存，缺少依赖时会失败；`-Preview` 仅显示工作目录和参数，不运行测试。

| `-Suite` | 测试范围 | 外部影响与前置条件 |
|---|---|---|
| `Default`（默认） | 全部默认自动化测试 | H2及邮件替身，手动项跳过 |
| `Database` | `ManualDatabaseConnectionTests`、`ManualMarketplaceTests`、`ManualAcceptanceFlowTests` | 需要local开发库；部分写入回滚，随机业务记录按本轮编号清理，邮件替身 |
| `Reliability` | `ManualReliabilityMySqlTests` | 创建并删除随机临时MySQL库，需建库权限，邮件替身 |
| `Acceptance` | `ManualAcceptanceKitTests` | 创建或重置带合法标记的独立验收库，需Node.js；保留干净基线，邮件替身 |
| `Schema` | `ManualSchemaMigrationTests` | 直接补齐开发库部分业务表/字段/约束，先备份并核对结构 |
| `Mail` | `ManualMailSendTests` | 向local配置的 `app.mail.test-recipient` 实际发信 |

例如，真实数据库闭环使用 `./tools/Test-Backend.ps1 -Suite Database`；仅查看将要执行的迁移命令使用 `./tools/Test-Backend.ps1 -Suite Schema -Preview`。

原有Maven入口继续有效。在 `backend` 目录执行默认套件的等价命令为：

```powershell
mvn "-Dmail.test.enabled=false" "-Ddb.test.enabled=false" "-Dschema.update.enabled=false" "-Dacceptance.kit.test.enabled=false" "-Dreliability.mysql.enabled=false" test
```

手动类根据各自system property显式启用；共享的 `db.test.enabled` 控制3个数据库类。默认跳过9项，不能把跳过项记作通过。

## 4. 核心手工闭环

以下为待执行检查，不因自动化或历史记录通过而自动勾选。

| 步骤 | 操作 | 预期 |
|---|---|---|
| 1 | 请求注册验证码 | 实际收到随机六位验证码，响应不包含验证码 |
| 2 | 六十秒内重发 | 429，带 `Retry-After` |
| 3 | 使用邮件验证码注册 | 201，已认证普通用户，尚未登录 |
| 4 | 登录并读取本人信息 | 200，独立Cookie生效 |
| 5 | 卖家上传图片并发布商品 | 201，搜索及分类能检索到在售商品 |
| 6 | 买家申请 | 201，交易 `PENDING` |
| 7 | 卖家接受 | 交易 `ACCEPTED`，商品 `TRADING` |
| 8 | 买家确认 | 仅买家确认，交易仍 `ACCEPTED` |
| 9 | 卖家确认 | 交易 `COMPLETED`，商品 `SOLD`，其余待处理申请取消 |
| 10 | 双方评价 | 各201，重复409，信誉更新 |
| 11 | 退出后读取本人信息 | 退出204，本人信息401 |

- [ ] 注册、登录和不同身份隔离完成。
- [ ] 图片、发布、检索、交易及评价闭环完成，并核对实际数据库状态。

## 5. 异常与治理检查

- [ ] 验证码错误、到期、消费及五次错误锁定；发送状态和实际收件一致。
- [ ] 未登录发布、跨用户修改、非交易双方访问、重复申请均被拒绝。
- [ ] 多买家可申请，接受一笔后不能接受另一笔；取消已接受交易恢复在售，已完成交易不能取消。
- [ ] 注销密码错误返回400及 `PASSWORD_MISMATCH`，原会话可继续使用；已接受交易阻止注销。
- [ ] 账号状态或会话版本在鉴权后变化时注销被拒绝；提交后并发退出不把成功变成500。
- [ ] 完整及编码站内图片URL不能绕过归属检查；引用中图片保留，解除引用并超过宽限期后清理。
- [ ] 既有完整站内图片URL商品重新保存后，地址规范化并补登记引用。
- [ ] 举报、管理员处理、举报人申诉、管理员复核及审计正确；卖家不能自行恢复隐藏商品。
- [ ] 管理员解除隐藏有权限和理由校验，未售恢复下架、已售保持已售；账号禁用/恢复后旧会话不可复用。
- [ ] 收藏幂等及隔离、求购分类搜索和关闭权限正确。
- [ ] 代理名单、真实客户端IP限流、HTTPS Cookie和浏览器来源在部署环境正确。

## 6. 待确认业务规则

已确认方向为校园邮箱验证码、邮箱密码登录、学校域名精确匹配、多个买家申请和双方确认成交。以下为当前实现，仍需团队确认参数或细节；文档整理不视为规则获批。

| 项目 | 当前实现 |
|---|---|
| 验证码 | 六位、五分钟有效、六十秒重发、五次错误锁定 |
| 接受和取消 | 接受后锁商品并保留其他申请，双方均可取消未完成交易 |
| 成交 | 双方确认后已售，自动取消其他待处理申请 |
| 评价 | 一至五分，完成交易双方各一次 |
| 申诉 | 举报人对已处理举报申诉一次，成立后重开，不自动撤销处置 |
| 商品恢复 | 管理员单独解除隐藏，未售先下架，已售保持已售 |
| 注销 | 管理员不能自行注销，注销不可恢复且邮箱不能重新注册 |

邮箱变更/重新认证、密码修改找回、交易超时及被处罚者申辩尚无已确认方案，不计入当前完成项。
