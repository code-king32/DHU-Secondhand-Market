# 后端审查与优化记录

2026-10-31，基于 `2a40a57` 的工作区改动。检查范围包括后端全部业务模块、公共鉴权与限流、邮件投递、图片存储、SQL结构、测试入口及部署配置。变更保留在工作区，未提交或部署。

## 已处理的问题

| 问题 | 原行为及影响 | 修复与证据 |
|---|---|---|
| URL携带会话凭据 | 无Cookie客户端把有效会话ID放入 `;jsessionid=`，仍可读取本人信息，扩大日志、历史记录等泄露凭据的风险 | 仅启用Cookie跟踪；真实HTTP回归从200变为401 |
| 会话有效期被写死 | 登录后强制设置1800秒，覆盖部署的Session超时配置 | 移除覆盖，真实HTTP测试以7分钟配置验证得到420秒 |
| 资料更新未复核会话撤销 | 首次鉴权后会话版本改变，原请求仍可写入昵称 | 账号行锁内重新鉴权，验证失败时不修改资料 |
| 并发退出可能500 | 取得Session后，另一请求使其失效，重复invalidate抛异常 | 退出保持幂等；模拟已失效Session仍返回204 |
| 不可见文字绕过必填 | 商品标题、描述和昵称可仅为NBSP、零宽字符等，原检查与社区模块不一致 | 共用文字空值判断；覆盖商品、注册、资料修改及验证码不被错误消费 |
| JSON隐式转换 | 小数商品ID被截断为整数；请求体可附带第二份JSON | 关闭整数小数转换并拒绝尾随文档；无效请求400且不创建交易 |
| 参数错误响应不一致 | 非数字页码或路径ID缺少约定的message | 统一参数缺失和类型错误的400响应 |
| 限流表满后误拒绝 | 按规则总数计算新增容量，已有计数也被容量上限拦截；每次请求扫描整个表 | 仅计新增条目；同秒最多清理一次。容量边界、过期、并发及既有限额回归通过 |
| 同账号限流可被换写法绕过 | MySQL的 `utf8mb4_0900_ai_ci` 把部分带重音字符的邮箱视为同一账号，输入字符串哈希却不同 | IP先限流，账号按数据库实际命中的邮箱计数。六种写法、六个IP的第六次被429拦截；真实MySQL验证字符串等价关系 |
| 注册与发码竞态 | 发码预检后若注册完成，仍可新建验证码和投递任务 | 锁住邮箱记录后再次检查注册状态；确定性交错回归从200变为409，不留下验证码和任务 |
| 信誉统计额外查询和快照差异 | 评价数量与均分分别查询，期间新增评价可能产生不一致组合；均分经过Double转换 | 同一条聚合SQL读取数量和均分，直接按BigDecimal保留两位小数，减少一次查询 |

修改了限流配置注释：实现是从首次请求起算的固定窗口，并非严格滑动窗口。默认额度未改变。

## 仍建议继续处理

以下是代码检查确认的缺口或扩展前的优化点，不表示已经完成压力测试，也不应与已修复项混淆。

| 优先级 | 事项 | 依据与建议 |
|---|---|---|
| P2 | 注销密码确认缺少独立限流 | `AccountController.close` 的密码校验未接入AbuseProtection。建议按账号及IP限制错误密码确认次数；避免持有会话者反复猜密码或持续触发BCrypt及账号锁等待 |
| P2 | 会话撤销对已开始写请求的语义不统一 | 注销和本次资料更新会在锁内复核会话版本；商品、社区和图片写操作主要在锁内复核账号可用状态。若要求撤销立即阻断已鉴权但尚未提交的请求，应传递包含会话版本的操作身份，并统一在事务锁内校验；当前后续新请求仍会被SessionAuth拒绝 |
| P2 | JSON体与图片解码并发预算 | 当前明确配置的是multipart大小、单图字节数/像素数及用户存储配额。建议额外限制JSON请求体大小，并对并发图片解码设置预算，做小堆内存环境压力验证 |
| P2 | 后台任务隔离和可观测性 | 邮件与图片共用默认调度执行环境；邮件批处理同步调用SMTP，图片每轮最多清理200个候选、默认每小时执行。建议分离调度资源、按积压量调整清理预算，并记录任务积压、失败次数和最旧任务年龄，确认SMTP延迟不会长期推迟图片清理 |
| P3 | 搜索与深分页 | 商品搜索使用带前导通配符的LIKE和LOWER，列表使用COUNT及OFFSET。数据增长后先用真实规模数据查看执行计划，再考虑中文全文索引、游标分页；不建议没有测量就批量加索引 |
| P3 | 完整HTTP错误契约及API缓存 | 此次统一了常用400错误；建议补齐405/415等框架错误的契约检查，并为身份、交易等敏感响应显式设置缓存策略 |

现有部署文档限定单实例。多实例会话、共享限流与共享图片存储需要在扩容时设计，本次未扩展部署架构。
