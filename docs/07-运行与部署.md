# 运行与部署

本文件统一维护非前端的环境配置、启动、生产打包、代理和备份说明。业务接口见对应接口文档，结构准备见[数据库与迁移](03-数据库与迁移.md)，测试及验收状态见[联调验收清单](06-联调验收清单.md)。

## 1. 环境与配置文件

| 项目 | 约定 |
|---|---|
| Java / Maven / MySQL | JDK 17、Maven、MySQL 8.0 |
| 仓库脚本 | PowerShell 7，命令从仓库根目录执行；脚本内部定位文件 |
| 后端地址 | 开发与验收均为 `http://localhost:8080` |
| 公共默认参数 | `backend/src/main/resources/application.properties`，不放连接凭据 |
| 开发示例 | [application-local.properties.example](../backend/config/application-local.properties.example) |
| 生产示例 | [application-prod.properties.example](../backend/config/application-prod.properties.example) |
| 自动加载边界 | `backend/config/` 仅放示例；必须复制后按 profile 或外部目录加载 |

Maven 交付 JAR 排除 `application-local.*` 和 `application-prod.*`，防止开发机配置随构建产物分发。它们仍可用于本机 `spring-boot:run` 和显式手动测试。环境文件、`.env`、图片和密钥受 Git 忽略规则保护，示例文件可提交。

## 2. 本地开发

先初始化数据库，再从仓库根目录复制配置；已有本地文件时编辑原文件，保留连接信息：

```powershell
Copy-Item backend/config/application-local.properties.example backend/src/main/resources/application-local.properties
```

模板使用下列环境变量；也可在被忽略的本地文件中填写实际值。

| 变量 | 用途 |
|---|---|
| `DB_URL` | 可选，默认本机3306端口的 `dhu_secondhand`，时区 Asia/Shanghai |
| `DB_USERNAME` / `DB_PASSWORD` | 数据库账号及密码 |
| `MAIL_HOST` / `MAIL_PORT` | 默认 `smtp.qq.com` / `465` |
| `MAIL_USERNAME` / `MAIL_PASSWORD` | 发件账号及 SMTP 授权信息 |

邮件示例使用 SMTP SSL；其他服务须按其要求修改 SSL/STARTTLS 配置，不应只替换端口。连接、读取和写入超时示例均为5秒。固定真实邮件测试还需在本地设置 `app.mail.test-recipient`；正常默认测试不需要实际收件。

```powershell
cd backend
mvn spring-boot:run "-Dspring-boot.run.profiles=local"
```

新终端可执行 `curl.exe -i "http://localhost:8080/api/goods"` 检查后端。空列表正常返回200；8080没有页面首页。前端启动和代理使用其独立 README；本机联调统一使用 localhost 或127.0.0.1，避免混用 Cookie 主机名。

## 3. 公共参数与持久化路径

公共参数按 HTTP与会话、来源与代理、图片、SQL初始化、邮件任务、限流分组。默认值以 `application.properties` 为准；验证码六位、五分钟有效、六十秒重发和五次错误锁定目前为代码内规则，不能通过新增无效配置项改变。

图片默认相对于后端工作目录保存在 `uploads/images/`，邮件任务密钥为 `uploads/mail-code.key`，首次发信时自动生成。更换工作目录会影响相对路径，生产环境应使用绝对路径。图片每人默认100张、100 MB，闲置24小时后可清理；后台默认每小时检查图片、每5秒检查邮件任务。

## 4. 生产构建与启动

在仓库根目录先执行默认测试，再打包：

```powershell
./tools/Test-Backend.ps1
cd backend
mvn package -DskipTests
```

产物为 `backend/target/secondhand-0.0.1-SNAPSHOT.jar`。`-DskipTests` 仅用于前一步测试已通过的打包；此构建不会把 local/prod 环境文件装入 JAR。

在部署目录准备 `config/application-prod.properties`，内容基于生产示例，并配置数据库、SMTP、图片目录、密钥路径和浏览器来源。生产变量 `DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、`MAIL_HOST`、`MAIL_USERNAME`、`MAIL_PASSWORD`、`IMAGE_DIRECTORY`、`MAIL_KEY_FILE`、`WEB_ALLOWED_ORIGINS` 为必填，`MAIL_PORT` 默认465，`TRUSTED_PROXIES` 默认空。

维护人员应先创建全部14张应用表。生产模板关闭应用自动建表，启用 Secure Cookie，要求浏览器通过 HTTPS 访问。将 JAR 放到部署目录，从该目录启动：

```powershell
java -jar secondhand-0.0.1-SNAPSHOT.jar --spring.profiles.active=prod
```

Spring Boot 会读取当前工作目录 `config/` 内的 profile 配置。若使用其他配置目录，可显式追加 `--spring.config.additional-location=file:C:/DHU-Market/config/`，目录路径末尾保留 `/`。环境变量在运行服务的进程中设置，不写进提交或验收截图。

## 5. 反向代理

登录和发信默认只使用 TCP 对端 IP。通过代理部署时，`app.web.trusted-proxies` 填写实际代理的精确 IP，逗号分隔，支持 IPv4/IPv6，不接受主机名或 CIDR。应用从 `X-Forwarded-For` 链右侧跳过可信代理，选取第一个不可信节点限流；不可信来源提交的转发头会被忽略。

保留 `server.forward-headers-strategy=none`，避免容器预先改写对端地址。单层 Nginx 的 `/api/` 代理可使用：

```nginx
location /api/ {
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 6m;
    proxy_pass http://127.0.0.1:8080;
}
```

`app.web.allowed-origins` 设置浏览器实际访问的完整来源，例如 `https://market.example.edu.cn`，不要只写域名或放入不受信任来源。多层代理须把可验证的代理逐个加入名单，入口代理应覆盖外部伪造头。Session 和限流仍为单实例内存状态，本说明不代表已完成多实例部署。

## 6. 备份、恢复和验收

备份至少包括数据库、`app.images.directory` 和 `app.mail.key-file`。恢复时保持三者对应关系；丢失图片不能仅靠数据库恢复，丢失密钥会影响尚未完成的加密邮件任务。

部署验收记录应包含代码版本、部署地址、实际数据库、Cookie及来源行为、图片上传读取、验证码收件和完整交易治理流程。H2测试、JAR打包或代理示例检查通过，均不能替代这些真实环境验收。
